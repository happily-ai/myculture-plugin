# MyCulture plugin evals

End-to-end cases for the jobs a customer brings to an assistant connected to MyCulture. Each case gives the assistant a realistic request. MyCulture tool calls are answered by mocks of the MCP 1.7.0 tools for a made-up company, and graders check the reply.

## Run

From the plugin folder:

```bash
cd myculture
claude plugin eval . --ablation none --no-publish
claude plugin eval . --ablation none --no-publish --tag results   # one journey
claude plugin eval . --case 'create/*' --runs 1                 # quick check
```

`--no-publish` keeps the HTML report local. Results go to `evals/results/`, which git ignores.

## Groups

| Group | Journey | Cases |
| --- | --- | --- |
| `start/` | Getting started | first run, missing results permission |
| `create/` | Creating an assessment | preview and stop, confirmed create, add a module, pre-approval still previews, Thai request, invite only named people |
| `results/` | Reading results | explain one result, compare in the given order, "who should we hire", section without a band, masked email |
| `answer/` | Questions about MyCulture | modules from the tool, can't delete an assessment |

Each case's `tags` include its group name. Write cases also carry `guardrail`.

## How a case is graded

- **`tool_used`**: the assistant called the tool the job needs. With `min: 0` and `max: 0` it asserts a tool was not called, for example no `confirm: true` in the turn that made the preview. Tool names take the form `mcp__plugin_myculture_myculture__<tool>`.
- **`llm` with `focus: trace`**: judges the final reply against the tool results. The trace doesn't include the user's request, so the grader quotes it.

The runner has no multi-turn cases, so a case that confirms a preview carries that preview inside the prompt.

## Mocks

One file per tool in `mocks/myculture/<tool>.md`, generated by `python3 scripts/gen_mocks.py myculture/evals/mocks/myculture` from the repo root (edit the script, not the files). `mocks/myculture/_tools.json` is the tool list the mock server exposes, copied from `myculture-functions` `eval/tools/1.7.0.json` (server 1.7.0, captured 2026-11-11T06:57Z, commit `ea230de`).

- Tools that answer the same for any input return a fixed JSON body.
- Lookups by id (`get_candidate_result` by `candidate_id`) are `type: agent` mocks: one `## <field> = <key>` JSON entry per key, returned exactly as written.

When the MCP's tools change, refresh `_tools.json` from the new snapshot in `myculture-functions` and update the mocks and skills that use the changed tools.
